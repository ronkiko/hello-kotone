# KOTONE ATLAS SHEET RULES — CANONICAL STANDARD v1

## 1. Назначение документа

Этот документ определяет **полные правила создания, проверки и приемки листов атласа Котоне**.

Он действует совместно с документом:

**KOTONE ATLAS SHEET TEMPLATE — FIXED STANDARD v1**

Разделение ответственности такое:

- **RULES** определяет, *что именно должно быть изображено и какие художественные/анимационные ограничения обязательны*;
- **TEMPLATE** определяет, *как именно физически размечается лист: размеры холста, frame boxes, бордеры, прозрачность, интервалы, title/footer и координатная сетка*.

Все листы для фреймов Котоне **обязаны размечаться строго по FIXED TEMPLATE**.

Генератору запрещено самостоятельно менять геометрию листа.

---

# 2. Один лист = один asset

На одном листе допускается только:

- одна конкретная анимация;
- одно направление;
- один asset ID.

Примеры:

- `kotone_idle_front`
- `kotone_walk_right`
- `kotone_jump_back`
- `kotone_run_left`

Запрещено объединять на одном листе:

- разные направления;
- разные действия;
- jump + landing;
- run + stop;
- несколько asset ID;
- несколько вариантов одного asset.

---

# 3. Стандартное количество кадров

Если для конкретного asset отдельно не утверждено иное:

**каждый animation sheet содержит ровно 6 кадров.**

Запрещено самовольно делать:

- 4 кадра;
- 5 кадров;
- 8 кадров;
- другое количество.

Смысловые стадии движения распределяются внутри 6 кадров и не меняют их количество.

---

# 4. Раскладка кадров

Все 6 кадров должны находиться:

- строго в один горизонтальный ряд;
- слева направо;
- без переноса;
- без второго ряда.

Разрешенная последовательность:

`1 2 3 4 5 6`

Запрещено:

- `3×2`;
- `2×3`;
- вертикальная колонка;
- staggered layout;
- диагональная раскладка;
- несколько рядов.

Физическая геометрия этой раскладки определяется **FIXED TEMPLATE**.

---

# 5. Структура листа

Каждый лист состоит из трех отдельных зон:

1. **TITLE BAR**
2. **MAIN FIELD**
3. **FOOTER BAR**

Эти зоны обязаны соответствовать координатам и размерам из **FIXED TEMPLATE**.

Title bar и footer bar:

- не перекрывают персонажа;
- не заходят в рамки кадров;
- не уменьшают полезную площадь кадров;
- не накладывают текст поверх арта.

---

# 6. Прозрачность MAIN FIELD

MAIN FIELD должен иметь **настоящую прозрачность PNG/RGBA**.

Запрещено использовать вместо transparency:

- белый фон;
- черный фон;
- серый фон;
- цветной фон;
- градиент;
- декоративную подложку;
- нарисованную шахматку.

Шахматка может отображаться только интерфейсом просмотра PNG как визуализация alpha.

Она не должна быть частью изображения.

---

# 7. Геометрия frame box

Физическая разметка каждого кадра определяется **FIXED TEMPLATE**.

Для текущего template:

- virtual frame: `640×640 px`;
- transparent gap: `5 px`;
- drawn border: `1 px`;
- outer frame box: `652×652 px`;
- frame spacing: `24 px`.

Все frame boxes:

- одинакового размера;
- квадратные;
- имеют углы строго 90°;
- не имеют rounded corners.

---

# 8. Виртуальный бордер

Каждый frame имеет **virtual border**.

Virtual border:

- не рисуется;
- является реальной внутренней границей безопасности;
- определяет максимальную допустимую территорию арта.

Ни один пиксель персонажа или VFX не может пересекать virtual border.

---

# 9. Отрисованный бордер

Каждый frame имеет видимый **drawn border**.

Он должен:

- иметь толщину ровно `1 px`;
- быть квадратным;
- иметь углы 90°;
- полностью обхватывать virtual border;
- находиться на `5 px` дальше наружу относительно virtual border.

Между virtual border и drawn border остается прозрачная защитная зона.

---

# 10. Safe margin внутри virtual border

Даже внутри virtual border арт не должен располагаться вплотную к границе.

Между крайним пикселем арта и virtual border должен оставаться визуально очевидный прозрачный запас.

То есть:

- волосы не касаются virtual border;
- стопы не стоят вплотную к нижней границе;
- вытянутая рука не упирается в боковую границу;
- юбка и одежда не цепляют край;
- VFX не обрывается на границе.

Это нужно для безопасной нарезки.

---

# 11. Что обязано находиться внутри virtual border

Полностью внутри virtual border должны помещаться:

- голова;
- волосы;
- лицо;
- руки;
- кисти;
- ноги;
- стопы;
- каблуки;
- босые ступни;
- одежда;
- юбка;
- рукава;
- lanyard;
- badge;
- волосы в движении;
- motion lines;
- wind streaks;
- particles;
- dust;
- energy VFX;
- effect trail;
- любые другие элементы конкретного кадра.

Ничего не может пересекать virtual border.

---

# 12. CORRUPTED FRAME RULE

Кадр автоматически считается **CORRUPTED**, если выполняется хотя бы одно условие:

- часть тела пересекает virtual border;
- волосы пересекают virtual border;
- рука обрезана;
- нога обрезана;
- стопа или каблук обрезаны;
- одежда обрезана;
- VFX пересекает virtual border;
- trail обрезан;
- арт касается drawn border;
- часть соседнего кадра попадает внутрь текущего;
- содержимое соседних кадров визуально пересекается;
- персонаж или эффект выходит за территорию своего frame;
- frame выглядит так, будто его нельзя безопасно вырезать независимо.

Даже небольшое нарушение считается corruption.

Если хотя бы **один** из 6 кадров corrupted:

**весь лист не считается готовым.**

---

# 13. Независимость кадров

Каждый frame должен быть отдельным независимым sprite.

Запрещено:

- объединять персонажей между соседними кадрами;
- позволять волосам переходить из frame в frame;
- проводить общий trail через несколько кадров;
- делать единый cloud/VFX через весь лист;
- использовать один объект, пересекающий две рамки.

Каждый кадр должен быть пригоден для независимой квадратной нарезки.

---

# 14. Промежутки между кадрами

Между outer frame boxes должен сохраняться фиксированный промежуток согласно **FIXED TEMPLATE**.

Для текущего template:

**24 px**

Запрещено:

- уменьшать этот gap;
- ставить рамки вплотную;
- позволять artwork соседних кадров приближаться друг к другу настолько, что возникает визуальное пересечение.

---

# 15. Размер холста

Размер листа определяется **FIXED TEMPLATE**.

Текущий стандарт:

**4096×896 px**

Этот размер не меняется от одной стандартной анимации к другой.

Генератор не имеет права:

- делать лист уже;
- делать лист выше;
- менять aspect ratio;
- перекомпоновывать кадры из-за нехватки пространства.

Если конкретный будущий asset действительно не может быть реализован в текущем template без нарушения scale, он считается **out-of-standard** и требует отдельного утверждения другого template.

---

# 16. Масштаб персонажа

Котоне должна сохранять единый визуальный scale между всеми asset sheets одной серии.

Контролируется:

- размер головы;
- пропорции тела;
- относительная длина рук;
- относительная длина ног;
- ширина корпуса;
- размер лица;
- общий visual scale относительно frame box.

При этом **запрещено фиксировать высоту силуэта в пикселях**.

Котоне может:

- наклоняться;
- приседать;
- прыгать;
- падать;
- вытягиваться;
- лежать;
- принимать широкую позу.

Изменение bounding box из-за позы — нормально.

Не нормально:

- искусственно уменьшать персонажа ради вмещения;
- искусственно увеличивать его в другом кадре;
- менять анатомические пропорции.

---

# 17. Character design остается постоянным

Между кадрами меняется:

**POSE**

Не меняется:

**CHARACTER DESIGN**

Стабильными должны оставаться:

- рост и визуальный scale;
- анатомические пропорции;
- форма головы;
- лицо;
- глаза;
- грудь;
- талия;
- бедра;
- длина конечностей;
- прическа;
- длина волос;
- челка;
- одежда;
- длина рукавов;
- форма юбки;
- колготки;
- обувь, если она предусмотрена конкретным вариантом;
- цвета;
- освещение;
- уровень детализации;
- rendering style.

---

# 18. Симметричный дизайн

Базовый дизайн Котоне специально сделан симметричным для уменьшения ошибок генерации.

Полностью удалены из стандартного дизайна:

- сумка;
- часы.

Запрещено самовольно добавлять:

- браслеты;
- часы;
- side pouch;
- сумки;
- боковые украшения;
- случайные предметы в руках;
- аксессуары только на одной стороне;
- другие асимметричные элементы.

---

# 19. Канонический костюм

Стандартный игровой образ Котоне:

- розовое каре;
- розово-фиолетовые глаза;
- белая рубашка;
- длинные рукава;
- открытое декольте согласно текущему канону;
- темный приталенный жилет;
- темная юбка-карандаш;
- темные полупрозрачные колготки;
- черные или очень темные туфли-лодочки;
- центральный синий lanyard;
- центральный ID badge.

Если для конкретной сюжетной вариации утверждено изменение, например **вариант без туфель**, меняется только явно утвержденный элемент.

Все остальные элементы дизайна сохраняются.

---

# 20. Направления камеры

Направление должно строго соответствовать asset ID.

## FRONT

Котоне смотрит лицом к камере.

Не допускается:

- заметный 3/4;
- разворот в сторону;
- профиль.

## BACK

Котоне строго спиной к камере.

Не допускается:

- back 3/4;
- поворот через плечо;
- диагональный разворот;
- вид лица.

Для top/down movement движение `back` визуально направлено **от зрителя вверх по игровому экрану**.

## LEFT

Чистый профиль / игровое направление влево.

## RIGHT

Чистый профиль / игровое направление вправо.

---

# 21. Реальная последовательность анимации

Шесть кадров должны представлять реальную читаемую последовательность движения.

Запрещено:

- делать шесть практически одинаковых поз;
- просто копировать персонажа;
- случайно менять позы без логики движения;
- менять направление тела между кадрами.

Animation cycle должен читаться как непрерывное движение.

---

# 22. IDLE

Idle состоит из 6 кадров с небольшими естественными изменениями.

Допустимы:

- дыхание;
- минимальный перенос веса;
- небольшая работа плеч;
- едва заметное движение рук;
- небольшое движение волос;
- небольшой secondary motion одежды.

Idle не должен выглядеть как:

- walk;
- run;
- combat stance;
- dance;
- сильная жестикуляция.

Все 6 кадров должны быть различимыми, но движение остается спокойным.

---

# 23. WALK

Walk состоит из 6 читаемых фаз цикла шага.

Должны ощущаться:

- перенос веса;
- чередование ног;
- counter-swing рук;
- небольшое естественное движение корпуса;
- secondary motion волос и одежды.

Walk не должен превращаться в run.

---

# 24. RUN

Run должен визуально отличаться от walk.

Допустимы:

- более широкий шаг;
- сильная работа рук;
- выраженный наклон корпуса;
- более сильный secondary motion волос;
- более динамичные позиции ног.

Обычный run не должен выглядеть как dash или special skill.

---

# 25. JUMP

Jump всегда состоит из 6 кадров:

1. push-off;
2. early rise;
3. rising;
4. apex;
5. falling;
6. late fall / preparation for landing.

Jump и landing — **разные asset sheets**.

---

# 26. VFX обычного JUMP

Для обычного прыжка допустим максимум:

- легкое движение воздуха;
- мягкие wind streaks;
- естественное движение волос;
- естественное движение одежды.

Запрещено:

- камни;
- булыжники;
- большой debris;
- explosion;
- shockwave;
- огромная пыль;
- tornado;
- энергетическая атака;
- dash-like VFX.

Jump — физический прыжок, а не skill.

---

# 27. LANDING

Landing состоит из 6 кадров:

1. first contact;
2. compression;
3. deepest compression;
4. beginning recovery;
5. recovery;
6. transition to idle.

Допускается только небольшой локальный landing effect.

Landing не должен выглядеть как удар по земле или special attack.

---

# 28. DASH

Dash — отдельный skill и должен быть визуально отличим от run.

Допустимы:

- сильный наклон тела;
- speed streaks;
- wind trail;
- air vortex;
- легкий debris;
- пыль;
- энергетический след;
- ощущение резкого импульса.

Однако все VFX каждого кадра обязаны полностью помещаться внутри его virtual border.

---

# 29. VFX не объединяет кадры

VFX одного кадра не должен визуально продолжаться в следующий кадр на листе.

Запрещено:

- единый длинный вихрь;
- общий trail через несколько frames;
- единая линия движения на всю страницу;
- общая пыль между соседними frames.

Каждый frame — независимый sprite.

---

# 30. TITLE BAR

TITLE BAR оформляется согласно **FIXED TEMPLATE**.

Минимально он содержит:

- `KOTONE`;
- название действия;
- направление;
- asset/category;
- asset ID;
- `6 FRAMES`.

Пример:

`KOTONE — IDLE FRONT`

`EXPLORATION / IDLE`

`kotone_idle_front`

`6 FRAMES`

---

# 31. FOOTER BAR

FOOTER BAR оформляется согласно **FIXED TEMPLATE**.

Стандартная строка:

**PNG • TRANSPARENT BG • GAME READY**

Footer не пересекает MAIN FIELD.

---

# 32. Подписи отдельных фреймов запрещены

Отдельные фреймы **не подписываются**.

Запрещены:

- цифры `1–6`;
- `FRAME 1`;
- названия фаз;
- подписи под рамками;
- подписи внутри рамок;
- стрелки;
- номера поз;
- служебные annotations.

Номера используются только логически при обсуждении последовательности и **не рисуются на готовом atlas sheet**.

---

# 33. Генератор обязан следовать TEMPLATE

При каждой генерации сначала применяется:

**KOTONE ATLAS SHEET TEMPLATE — FIXED STANDARD v1**

После этого поверх template применяются правила данного документа.

Генератору запрещено самостоятельно:

- менять canvas;
- менять frame size;
- менять количество frames;
- менять row layout;
- менять spacing;
- менять border;
- добавлять подписи;
- заменять transparent BG шахматкой;
- объединять несколько assets;
- менять дизайн Котоне.

---

# 34. Приоритет правил

Если при генерации возникает конфликт, действует следующий приоритет:

1. один лист = один asset;
2. FIXED TEMPLATE;
3. 6 frames;
4. один горизонтальный ряд;
5. настоящая прозрачность MAIN FIELD;
6. virtual border и safety margin;
7. отсутствие corrupted frames;
8. постоянство дизайна Котоне;
9. правильное направление;
10. читаемая анимация;
11. корректный VFX.

Ни один художественный эффект не может служить оправданием для нарушения template.

---

# 35. Финальная приемка

Перед выдачей каждого atlas sheet визуально проверяются все 6 кадров.

## STRUCTURE

- [ ] один asset ID;
- [ ] одна анимация;
- [ ] одно направление;
- [ ] ровно 6 кадров;
- [ ] все 6 кадров в один горизонтальный ряд;
- [ ] лист соответствует FIXED TEMPLATE;
- [ ] размер canvas правильный;
- [ ] TITLE BAR отдельно;
- [ ] MAIN FIELD отдельно;
- [ ] FOOTER BAR отдельно.

## TRANSPARENCY

- [ ] MAIN FIELD реально прозрачный PNG/RGBA;
- [ ] внутри frames нет фоновой заливки;
- [ ] между frames прозрачность;
- [ ] safety gap прозрачный;
- [ ] шахматка не нарисована.

## FRAME GEOMETRY

- [ ] frame boxes квадратные;
- [ ] размеры соответствуют template;
- [ ] углы 90°;
- [ ] drawn border ровно 1 px;
- [ ] virtual border соблюден;
- [ ] drawn border вынесен на 5 px наружу;
- [ ] spacing между frames соответствует template.

## ART SAFETY

- [ ] персонаж полностью внутри virtual border;
- [ ] волосы полностью внутри;
- [ ] руки полностью внутри;
- [ ] ноги полностью внутри;
- [ ] стопы / обувь полностью внутри;
- [ ] одежда полностью внутри;
- [ ] lanyard и badge полностью внутри;
- [ ] VFX полностью внутри;
- [ ] есть прозрачный safe margin;
- [ ] арт не касается drawn border;
- [ ] ничего не обрезано;
- [ ] соседние frames не пересекаются.

## CHARACTER CONSISTENCY

- [ ] scale визуально постоянный;
- [ ] пропорции постоянные;
- [ ] лицо постоянное;
- [ ] волосы постоянные;
- [ ] костюм постоянный;
- [ ] палитра постоянная;
- [ ] свет постоянный;
- [ ] rendering style постоянный;
- [ ] нет сумки;
- [ ] нет часов;
- [ ] нет случайных аксессуаров.

## ANIMATION

- [ ] направление правильное;
- [ ] 6 кадров образуют осмысленную последовательность;
- [ ] кадры не являются копиями;
- [ ] движение соответствует action;
- [ ] VFX соответствует типу action;
- [ ] VFX не объединяет соседние frames.

## LABELS

- [ ] нет номеров отдельных frames;
- [ ] нет подписей фаз;
- [ ] нет текста внутри frame area.

---

# 36. Правило финального результата

Если хотя бы один пункт обязательной проверки не выполнен:

**лист не должен выдаваться как принятый результат.**

Если хотя бы один frame corrupted:

**весь atlas sheet считается corrupted.**

Исправляется весь лист или проблемный asset генерируется заново с сохранением того же FIXED TEMPLATE.

# 37. Связь RULES и TEMPLATE

Для всех стандартных листов Котоне действует:

**RULES + FIXED TEMPLATE = единый обязательный стандарт.**

RULES нельзя использовать без TEMPLATE.

TEMPLATE нельзя использовать без RULES.

То есть любой новый atlas sheet должен одновременно:

- соответствовать полной системе правил этого документа;
- быть физически размечен по **KOTONE ATLAS SHEET TEMPLATE — FIXED STANDARD v1**.

Генератор не проектирует лист.

Генератор **заполняет заранее утвержденный template**.
